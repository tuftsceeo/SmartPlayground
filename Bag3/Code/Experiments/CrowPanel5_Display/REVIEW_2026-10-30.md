# CrowPanel 5" teacher tool — UI review against the design canvas

Date: 2026-10-30, revised the same day against the updated canvas. Firmware: the code in
this folder as of commit `07f6e69`, as it runs on the CrowPanel 5.0 V3 board. The firmware has
not changed since the first pass; only the canvas has.

## How this was reviewed

- **Reference:** the design canvas, https://claude.ai/artifact/LiR5xAGC7LecrJh7BFb3iQ:
  page 1 ("Design 1") and the three expansion pages, "Send Code Expansion" (boards 4.1–4.6),
  "NFC Screen Expansion" (5.1–5.14 and "Tags Home") and "Connected Mode Expansion" (7.1–9.6).
  Board names in the tables (e.g. *4.3 SendPartial*) are the reference. Zoom mode (page 2) is
  out of scope.
- **Canvas revision:** the first pass used an earlier canvas. Since then, page 1 changed as
  well as gaining expansion pages:
  - *card* became *tag* everywhere, the home button "Cards" became "NFC Tags", and the tag
    screen's tabs became Games / Write / Read (Helper and My own are gone).
  - "Linked to ChatBroadcast" became "Connected". The Connected status screen lost Happening
    now / Recent and its footer; it shows a Status block, all 14 devices and a "Skipped" legend,
    and Stop all is always shown.
  - The link prompt became "Connecting · On the computer: Connect via USB", with no Just
    charge button.
  - The computer's tag request lost the tag chip, the "Radio paused" text pill (now an icon)
    and the "Last card" footer.
  - Timestamps are relative ("5 min ago", "Just now").
- **Screenshots:** the [review_shots/canvas/](review_shots/canvas/) renders are of the earlier
  canvas, kept for the layout comparison; they don't show the new copy. Device shots are
  unchanged because the code is unchanged. Rows for states that exist only on the new boards
  were reviewed against the code, not captured, and have no screenshot. Where the
  canvas and the code disagree on *appearance*, the canvas wins.
- **Behavior and gating:** a mock is not authoritative on what is enabled or what happens next.
  Rows where the canvas and the app *behave* differently are marked **needs your call** rather
  than given a fix.
- **Device captures:** every shot is a real LVGL frame taken on the board.
  - [shot.py](shot.py) runs on the device. It snapshots the screen and drives a virtual pointer,
    so taps go through LVGL's own hit-testing.
  - [shot_host.py](shot_host.py) is the host side: `exec`, `shot`, `tap` and `batch`.
  - The radio and `store.save` were stubbed in RAM throughout, so no packets reached wands and
    nothing was written to flash.
  - The 14 stand-in devices (12 wands, 2 stations) and the "Red table" group existed in RAM only.
- **"state forced":** rows marked this way had their state set from the REPL (for example an
  NFC result with no card on the reader, or a send-code progress mix). They show the UI's
  *response* to that state, not the path that produces it.
- **Scrolling labels:** text that looks cut off in a still frame (7h, 10c) is a scrolling label
  (`ui_kit.slot`, `SCROLL_CIRCULAR`) caught mid-scroll. That is intended and is not reported as
  clipping.
