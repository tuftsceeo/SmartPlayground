3Color picker concepts — restricted, playful palettes

Pickers for choosing among the segmentation's own colours plus custom additions (used wherever 2b/2c show a palette or "+ add custom colour"). Each is a small popover, ~220px, not a full page.

3aCrayon box
pick a colour×
+
tilted, hand-drawn wrapper labels: "cherry red", "leaf green"…
Each swatch drawn like a crayon (rounded tip, paper wrapper band), gently alternating tilt so they read as "in a box," not a grid. Segmentation colours get friendly names instead of hex. Dashed crayon at the end = add a custom one via the OS colour picker.
3bPaint-tray dabs
colours in this icon
+
tap a dab, then paint
Irregular blob shapes on a wooden-palette background, like dabs of paint already squeezed out. Reads as "these are the paints you mixed for this picture," reinforcing that the palette is drawn from the icon, not generic.
3cSpinner wheel
spin to pick
+
centre shows current pick
A dial with one peg per colour, current selection highlighted in the hub. Novel/fun but slower to operate than a grid — better as a fun secondary entry point than the primary picker.
3dSticker sheet
pick a sticker
+
peeled corner + drop shadow per chip
Rounded square chips with a lifted-corner/shadow treatment, laid out slightly offset like stickers on a sheet. Closest to a plain swatch grid in speed of use, with just enough personality via the peel detail and loose grid.

2Landscape, segmentation access, custom palette, clearer tools

Reworked for a landscape browser window (portrait as a rare fallback, not the design target). Three things solved here: (1) where posterization/detail & per-segment colour controls live now that they're not always on screen — a docked panel in Advanced, a slide-over overlay in Simple; (2) palettes now offer + custom colour alongside the segmentation's own colours, everywhere a palette appears; (3) the tool dock is 4 explicit, separately-labelled actions — draw / erase (off) / reset (back to segmentation) / undo — instead of the ambiguous pencil+backarrow pairing from the old screenshots. Also added the missing front door: the app needs a way to choose import new vs load example vs load from device before the editor even opens.

1Icon Display Station — layout options

Kid-Pix/MS-Paint best practices applied: canvas is the hero (biggest, centered), tools live in a persistent dock next to it (not scattered), palette & actions are big and colorful, jargon-y numbers are hidden. Playful pastel accents borrowed from WebApp2 (teal/purple/coral, pill buttons, rounded cards) instead of the current dark hacker-console look.
