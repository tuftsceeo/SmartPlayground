# Simulator / ChatBroadcast UI review — 2026-10-27

Observed issues only; each needs verification before work starts. Tested in ChatBroadcast simple
mode at `http://localhost:8767/BroadcastCode/ChatBroadcast/`, mostly at 1280×800, with spot checks
at 768px and 375px.

Games exercised: examples Shake Rainbow and Cooking; chat-made games Hot Potato (3 wands),
Color Stomp (1 wand + Splat), Team Splat Race (2 wands + 2 Splats), Weather Display (1 wand +
2 displays). All are in My saved games.

Screenshots in the review pane rendered at a different scale from click coordinates, so some
pointer-position results are marked **unconfirmed**.

## P0 — blocks or confuses a teacher

### 1. Previous game's LEDs persist on the wand
- Where: main wand, after New game or opening a saved game.
- Observed: Hot Potato's wand kept Cooking's green "egg" pixel through play, drawn over the red
  potato glow. Reopened Hot Potato and new Weather Display showed a Cooking-style yellow pattern
  before any input.

### 2. Multiple Device view keeps devices from the previous game
- Observed: Hot Potato opened as "4 wands and 1 display in this game", carried over from a Cooking
  session; Hot Potato has no display code. Team Splat Race also got an unused display.
- At 4 wands "+ Add a wand" disappeared with no message.

### 3. Multi-device games open with a single device
- Observed: Hot Potato (3 wands), Team Splat Race (2 wands, 2 Splats) and Weather Display
  (2 displays) all show one wand in the main view. Other devices are only in "View Multiple Device
  Simulation", and each added device needs a second click ("Click for simulation" /
  "Click to Add Display") to start.

### 4. Reopened saved games show internal content
- Where: My saved games → Cooking, Hot Potato.
- Observed: the chat begins with the hidden remix prompt ("I would like to remix the Cooking
  example… Here is the Cooking code:") followed by the full raw Python as a user message. Code
  blocks appear as "[code: 60 lines, sent to editor]". Suggestion chips from the end of the
  conversation are gone.

### 5. Raw code streams into the chat while a game is generated
- Where: every chat-generated game and remix.
- Observed: lines such as `got.append(cmd)` and `buz.reject()` appear as plain prose, unindented,
  for ~20 s, then collapse to a `python` chip with **Show** and **View code**. The wand area shows
  only a "wand preview" placeholder during this time for new games.

### 6. Assistant language is developer-facing
- Observed text: "I also removed the test-only code and the sound library import to keep the file
  small", "Code updated (v2)", a `python` label, two code buttons (Show / View code).
- Team Splat Race instructions: "The Splats must be paired first… The first wand to tap is the
  leader. When the leader's lights show 2 Splats, press its button."

### 7. Simulator stops after each change; overlay covers the wand
- Observed: after a chat update a "New code is ready / Play it →" card appears; after idle a
  "Simulation paused / play it to start again" card appears. Both cover the lower wand and status
  line; LEDs go dark until Play is pressed.

### 8. Splat team game could not be played
- Game: Team Splat Race.
- Observed: no way to pair Splats in the simulator and no hint how. Both wands' Splats are labelled
  "Splat 1". After shaking wand 2 and stomping its Splat, both stayed "white". A round could not be
  completed.

### 9. Two-display game: displays don't respond, and can't be told apart
- Game: Weather Display.
- Observed: tapping the sun tag lit the wand yellow; neither display changed. Both displays are
  labelled "Icon display". Nothing indicates whether a message reached a display.

### 10. Tag picker is clipped
- Main view (Cooking): the "Tap a tag" popover is cut off by the simulator card; bottom chips and
  the type box are partly hidden.
- Multiple Device view: the popover was entirely out of view; chips existed in the DOM below the
  visible area and could only be triggered by script.

### 11. Simulator squeezed in stacked layouts (768px, 375px)
- Observed: simulator area ~150–180px tall; wand cut off at the matrix; Tap a tag, Shake and slider
  only reachable by scrolling inside a nested scroll area. Chat takes the remaining height.

## P1 — missing feedback and inconsistency

### 12. Controls shown that the game doesn't use
- Color Stomp (tilt + button only) shows Jump, Spin, Shake, shake slider and Turn over.
- Team Splat Race (uses shake) shows Jump and Spin.

### 13. Wand shrinks when a Splat is present
- Observed: wand pad shrinks to make room for the Splat below; wand button becomes 31×31px.

### 14. Splat state not visible
- Observed: Splat state ("ready", "white") exists only in the button's accessible label; the icon
  looks the same in every state.

### 15. Tilt stays after the pointer leaves
- Observed: wand 1 in the Multiple Device view stayed at "Right Up" after the pointer left its pad.

### 16. Multi-tag games give little guidance
- Cooking card: "needs 5 NFC tags — multi-tag"; picker lists 8 tags.
- Picker closes after each tap.
- Status line never shows which tag was tapped (stays "Upright — running").
- Hot Potato's instructions say to tap "the game card" first; the picker only offers "potato".

### 17. Game name changes by itself
- "My Shake Rainbow" became "Shake Rainbow" and "My Cooking" became "Cooking" after the first chat
  reply.

### 18. Version label doesn't count
- Weather Display showed "Code updated (v1)" twice, after two different updates.

### 19. Assistant reply ends mid-sentence
- Weather Display: reply ends "the closest options I can build are:"; the options appear only as
  chips.

### 20. Multiple Device view labelling is inconsistent
- Wand 1 "This wand" (pink chip), added wands "Playing" (green chip), displays "Icon display"
  (purple chip).
- Only added wands have a remove ×; displays have none.
- "Tap a tag" is pink-outlined full-width in this view, grey in the main view.
- Display shows a full grid of green dots before the game has sent anything, with no label.

### 21. Unclear icon-only controls
- "Start over" is a broom/sparkle icon with no visible label.
- Game bar: + (New game, 30px, tooltip only), save and open are icon-only.

### 22. Shake control
- Slider reads "Shake ——— Strong" (no matching left label); track ~85×16px; labels 10px.
- LEDs respond ~1 s after Shake is pressed with no immediate pressed feedback.

### 23. Status line wording and size
- Text such as "Left Up — running", "Face Down — running"; 11px.
- **Unconfirmed:** "Face Down" shown while the wand appeared face up (possible click-scale artefact).

### 24. Layout shift while an example loads
- Pad first shows "Turn over"; on load it disappears and Shake + slider appear.

### 25. Duplicate and irrelevant suggestions
- Remix message lists "Ideas for a remix" and near-identical chips below it.
- Generic starter chips (e.g. "What can the big display do?") show above a loaded game.

### 26. Disabled buttons give no visible reason
- "Use as-is → send" and "Send to Device →" are greyed; the reason ("Connect to the Device first")
  is only in the accessible name.

### 27. Unsaved-changes dialog doesn't name the game
- "This game hasn't been saved yet" with Save & Continue / Discard / Cancel.

## P2 — design system, accessibility, polish

### 28. Accent colours
- Pink is the primary accent throughout; the only purple button is "View Multiple Device
  Simulation". "Connect" is teal.

### 29. Mixed fonts
- Pad hint ("move to tilt · click to press") and home tagline use Patrick Hand; the rest is Nunito.

### 30. Contrast
- Pad hint #8b859a at 14px on striped lavender (below 4.5:1).
- Disabled "Send to Device" is white on lavender.

### 31. Keyboard access
- Home `.splash-card` and gallery `.example-card` and saved-game cards are `div`s with no tabindex.
- (Simulator controls are labelled and focusable; Escape closes the Multiple Device view and returns
  focus.)

### 32. Touch targets under 44px
- Mute and Start over ~41×37; wand button 42×42 (31×31 with a Splat); New game 30px; saved-game
  Rename/Delete 35px.

### 33. Saved games list
- Every card has the same placeholder icon, no description, no device count.
- "Send games to NFC Station" is shown in simple mode.

### 34. Desktop whitespace
- App sits in a floating card with wide margins at 1280px.
- Example page: large gap between simulator and description; a detached shadow block under the
  simulator card.
- Rainbow and Shake Rainbow share an icon; gallery text "Jump (freefall)", "Multi-tag".
