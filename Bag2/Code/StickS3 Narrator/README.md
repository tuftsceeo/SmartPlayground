# StickS3 Wand Narrator

Listens for ESP-NOW broadcasts (`start_game`/`stop`, plus Freeze Dance's
raw Go/Freeze/Dance/Ready calls) and plays a matching WAV clip through the
speaker, plus shows the label on the color LCD.

Read-only on ESP-NOW -- reuses the `start_game`/`stop` payloads defined in
`../lib/espnow_manager.py` (bundled here). Never sends.

Hardware: M5Stack StickS3 (ESP32-S3), UIFlow2 MicroPython. Bench tested
against an M5Paper Remote (no wands) -- see the bench checklist below for
what's confirmed vs. still open.

## Files

| File | Role |
|---|---|
| `main.py` | Boot entry: M5 init, ESP-NOW (receive-only), poll loop |
| `demo.py` | Cycles through every phrase without ESP-NOW/hub/wand |
| `narrator_ui.py` | LCD text rendering |
| `phrases.py` | Tag -> spoken label + WAV path + LCD color |
| `espnow_manager.py` | Bundled copy of `../lib/espnow_manager.py` |
| `game_tags.py` | Bundled copy of `../lib/game_tags.py` |
| `boot.py` | Same as `../M5Paper Remote/boot.py` |
| `assets/_generate_phrases.py` | Not present in this checkout -- generates WAV clips via offline TTS |
| `assets/_simulate_text_fit.py` | Not present in this checkout -- generates `narrator_ui.py`'s `_LAYOUT_TABLE` |
| `assets/speech/*.wav` | Not present in this checkout -- upload to `/flash/assets/speech/` |

## ESP-NOW message handling

| Message | Handling |
|---|---|
| `start_game` | Plays clip, shows label |
| `stop` | Plays "Stopped" clip, shows "Listening..." |
| Freeze Dance raw `FD_GO`/`FD_FREEZE`/`FD_DANCE`/`FD_RESET` | Plays "Go"/"Freeze"/"Dance"/"Ready" clip |
| `find_device` | Rewritten to `start_game` name `"finddevice"` by `espnow_manager.py`; handled as a normal announcement |
| `status_poll` / `status_report` / `scan_request` | Ignored |
| Programming Station's scanned-color broadcast | Not handled |

`main.py`'s `_AnnounceDebounce` collapses repeats of the same tag within
`ANNOUNCE_REPEAT_GUARD_MS` (400ms), since senders re-send for reliability
(M5Paper Remote sends `start_game`/`stop` twice, `freeze_dance.py` sends
raw calls 5x).

Playback is delayed `PRE_PLAY_DELAY_MS` (400ms) after a message is
received, with `enow.drain()` called right before playback starts (not
after): ESP-NOW activity too close to a playback boundary produces an
audible pop on some clips, confirmed on the bench by A/B testing with
`test.py`. The delay also gives the resend time to arrive so `drain()` can
discard it before playback starts.

## Icon colors

`phrases.py`'s `GAME_ICON_COLORS`/`FREEZE_DANCE_CALL_COLORS` set the LCD
background color per tag -- hand-copied from `../lib/leds.py`'s palette and
scaled by the same factor `Live_Page/wand_icons.html` uses. Not confirmed
against the wand's actual LED output.

| Tag | Color |
|---|---|
| `cooking` | amber |
| `melody` | teal |
| `simpleicecream`, `multiicecream` | white |
| `freezedance` | white |
| `shakerainbow` | white |
| `colorquest` | dark green |
| `fd_go` / `fd_freeze` / `fd_dance` | green / red / purple |
| `fd_reset` | white |
| `jumpin`, `shake`, `jump`, `sound`, `nfcsound`, `rainbow`, `gestures` | none (neutral blue) |

## Text sizing

`narrator_ui.py`'s `_LAYOUT_TABLE` holds `(font_size, line splits)` per
label, generated by `assets/_simulate_text_fit.py` (not present in this
checkout). A label not in the table uses `_fallback_layout`'s single-line
estimate.

## Generating the spoken clips

```bash
pip install pyttsx3
python assets/_generate_phrases.py
```

(script not present in this checkout). Produces mono 16-bit PCM WAV @
16000 Hz. Re-run when `phrases.py`'s labels change.

## Uploading to the device

1. Flash UIFlow2 MicroPython (via
   [M5Burner](https://docs.m5stack.com/en/quick_start/m5burner)).
2. Copy `main.py`, `narrator_ui.py`, `phrases.py`, `espnow_manager.py`,
   `game_tags.py`, `boot.py` to the device root.
3. Copy `assets/speech/*.wav` to `/flash/assets/speech/`.
4. Reboot.

```bash
mpremote connect /dev/cu.usbmodem1101 fs cp main.py narrator_ui.py phrases.py espnow_manager.py game_tags.py boot.py :
mpremote connect /dev/cu.usbmodem1101 fs cp -r assets/speech :assets/speech
mpremote connect /dev/cu.usbmodem1101 soft-reset
```

(swap the port for whatever `ls /dev/cu.usbmodem*` shows).
